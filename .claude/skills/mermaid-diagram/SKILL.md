# Mermaid 아키텍처 다이어그램

`src/` 디렉토리를 분석해 컴포넌트 의존성 그래프와 상태 흐름을 Mermaid로 그려 정적 HTML로 저장하고 브라우저로 연다.

## 절차

1. **소스 분석**
   - `src/` 하위 전체 파일을 탐색(Glob/Read)해 최신 구조 기준으로 분석한다. 과거 결과를 재사용하지 말고 재실행할 때마다 다시 스캔한다.
   - 각 파일의 `import` 문을 읽어 컴포넌트/모듈 간 의존 관계(누가 누구를 import 하는지)를 추출한다.
   - `createContext`/`Provider`/`use*` 커스텀 훅이 있는 파일(상태를 소유한 곳), `useState`/`useEffect`가 있는 파일, API 호출(`fetch` 등) 파일을 구분해 상태의 소유자와 소비자를 식별한다.

2. **다이어그램 두 종류 생성**
   - **컴포넌트 의존성 그래프 (필수, `flowchart TD`)**: 파일/컴포넌트를 노드로, import 관계를 화살표로 표현. Context 계층, API 계층, 컴포넌트 계층을 서로 다른 `subgraph`나 색상으로 구분해 계층 구조가 한눈에 보이게 한다.
   - **상태 흐름 다이어그램 (가능하면 추가, `flowchart` 또는 `sequenceDiagram`)**: 전역 상태(Context)가 어디서 만들어져 어떤 컴포넌트로 흘러가는지, 사용자 액션 → 핸들러 → Context 함수 → API 호출 → 상태 갱신 → 리렌더로 이어지는 왕복 흐름을 표현한다.

3. **HTML 산출물 작성**
   - Mermaid.js는 CDN `<script>` 태그로 로드해 정적 파일 하나로 완결되게 한다.
   - 다이어그램별로 섹션 제목을 붙이고, 다이어그램이 커질 경우를 대비해 가로 스크롤 컨테이너를 적용한다.
   - 저장 경로: `docs/architecture/index.html` (디렉토리가 없으면 새로 생성).

4. **브라우저로 열기**
   - OS를 감지해 알맞은 명령을 사용한다: macOS → `open`, Windows → PowerShell `Start-Process` (또는 `start`), Linux → `xdg-open`.
   - 파일 생성 직후 자동으로 실행한다 — 별도 요청 없이 바로 열어서 보여준다.

## 참고

- 이 스킬은 특정 컴포넌트 이름을 하드코딩하지 않고 `src/` 구조를 가진 프로젝트라면 일반적으로 동작하도록 작성한다.
- 다이어그램 정확도가 최우선이므로, import 관계나 상태 흐름을 추측하지 말고 실제 코드를 읽어서 반영한다.
