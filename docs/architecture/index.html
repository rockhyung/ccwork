3. 상태 흐름 — 노트 생성 / 수정 (저장 버튼)

NoteEditor의 저장 버튼 클릭부터 서버 응답 후 리렌더까지의 왕복 흐름. 생성/수정 모두 API 응답을 기다린 뒤에만 로컬 상태를 갱신한다(낙관적 업데이트 없음). 

sequenceDiagram
  participant User as 사용자
  participant Editor as NoteEditor
  participant Ctx as NotesContext (useNotes)
  participant Api as api/notes.ts
  participant Server as json-server

  User->>Editor: 저장 버튼 클릭 (handleSave)
  alt 새 노트 생성 (isCreating)
    Editor->>Ctx: createNote(title, content)
    Ctx->>Api: api.createNote({ title, content })
  else 기존 노트 수정
    Editor->>Ctx: updateNote(id, { title, content })
    Ctx->>Api: api.updateNote(id, updates)
  end
  Api->>Server: fetch POST/PATCH /notes
  Server-->>Api: 저장된 Note (createdAt/updatedAt 포함)
  Api-->>Ctx: Promise<Note> resolve
  Ctx->>Ctx: setNotes(prev ⇒ 추가 또는 교체)
  Ctx-->>Editor: notes 갱신 → 리렌더
  Editor-->>User: onDone() 호출

  Note over Editor,Api: 실패 시 catch(e) => console.error(e)만 수행 (alert 없음)
